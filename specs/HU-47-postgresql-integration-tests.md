## 1. Context and goal
All 152 backend tests run without a database: handlers use in-memory repositories and the HTTP tests
replace the repositories too. That leaves real risks untested:

- the EF Core migrations (`AddSubscriptionsTable`, `AddUsageRecordsTable`, `AddUserOwnership`) and the
  model snapshot can drift from the entity configuration;
- PostgreSQL constraints (`CHECK`, `NOT NULL`, FK `ON DELETE CASCADE`), column types (`numeric(18,2)`,
  `date`, `timestamptz`) and snake_case naming are only checked by hand;
- the real repositories' LINQ (owner predicates, ordering, paging, date ranges) is translated to SQL that
  no test executes.

Goal: an automated suite that runs the real migrations and the real API against a **disposable
PostgreSQL** container, locally and in CI, with synthetic data only.

## 2. Scope
**In scope:**
- Test harness with **Testcontainers for .NET** (`Testcontainers.PostgreSql`): one throwaway
  `postgres:17-alpine` container per test run (same major version as `docker-compose.yml`).
- Migration, schema and constraint tests; real-repository tests; HTTP tests over the real
  Infrastructure (fake authentication scheme from HU-12, no Auth0).
- Running the suite in the existing CI workflow (GitHub-hosted Ubuntu runners include Docker).

**Out of scope:**
- Browser E2E (HU-48); performance/load tests; testing Auth0 itself.
- A second test project (see §12).
- Changing production code, except a defect found by these tests (fixed in the same story and recorded
  in §14).

## 3. Functional requirements
- **FR-1:** A shared fixture starts one PostgreSQL container per test run, applies the real migrations with
  `Database.MigrateAsync()` and disposes the container at the end.
- **FR-2:** Every database test starts from empty tables (`TRUNCATE subscriptions, usage_records CASCADE`)
  so tests are independent and order-free.
- **FR-3:** Database tests are grouped in one xUnit collection (run sequentially against the shared
  container) and tagged `[Trait("Category", "Integration")]`.
- **FR-4:** HTTP integration tests host the real API with `WebApplicationFactory`, the real repositories
  and the container's connection string; only authentication is replaced (fake scheme, subject header).
- **FR-5:** The default `dotnet test` runs everything (CI included). Developers without Docker can run
  `dotnet test --filter "Category!=Integration"`.
- **FR-6:** No real credentials, Auth0 tenant or personal data: the container password is generated by
  Testcontainers and test rows use synthetic owners (`it|owner-a`, `it|owner-b`).

## 4. Business rules
Unchanged. The suite verifies the existing rules against PostgreSQL.

## 5. Acceptance criteria
- **AC-1:** Given an empty database, when the migrations run, then the schema has the expected snake_case
  tables, columns, types, check constraints, indexes and FK, and `HasPendingModelChanges()` is `false`.
- **AC-2:** Given direct SQL that violates an invariant (amount ≤ 0, empty owner, negative usage count),
  when it is executed, then PostgreSQL rejects it.
- **AC-3:** Given a subscription with usage records, when it is deleted, then its usage records are deleted
  (cascade).
- **AC-4:** Given two owners with data, when the real repositories and the API are used, then each owner
  only reads and changes its own rows (list, get, update, delete, summary, upcoming, usage, cost per use,
  simulation) and cross-owner ids return `404`.
- **AC-5:** Given the API over the real database, when a full CRUD flow runs, then status codes and
  persisted values match the contracts (`201`, `200`, `204`, then `404`; amounts with 2 decimals,
  `DateOnly` and UTC timestamps preserved).
- **AC-6:** Given no token, when a private route is called over the real database, then `401`; and
  `GET /api/health` reports the database as healthy (`200`).
- **AC-7:** Given CI, when the backend workflow runs, then the integration suite runs and passes,
  repeatably (two consecutive green runs), adding under two minutes to the job.

## 7. Data model changes

## 8. Validation and error cases
| Case | Expected result |
|---|---|
| Docker not running locally | Integration tests fail with a clear Testcontainers error; unit tests unaffected (use the filter in FR-5) |
| Migration and model snapshot out of sync | `HasPendingModelChanges()` test fails |
| Constraint missing from a migration | The matching constraint test fails |
| Test leaves data behind | Next test truncates first, so no cross-test effect |

## 9. Edge cases
- First CI run pulls the PostgreSQL image (~tens of MB); later runs on fresh runners pull again — accepted.
- `numeric(18,2)`: a value like `10.005` is rounded by the domain before persistence; the test asserts what
  PostgreSQL returns, not only what the domain sent.
- Time zones: `timestamptz` values are compared as UTC.
